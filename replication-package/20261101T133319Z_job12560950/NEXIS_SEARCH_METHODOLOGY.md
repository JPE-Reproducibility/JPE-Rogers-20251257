# Nexis Uni search/extraction methodology (Appendix liability analysis)

**Supporting reference; `README.md` governs.** `README.md` is the single documentation point for this
package; this file is the extraction detail behind its Nexis Uni entry.

The Appendix liability/tort and bankruptcy measures are built from **Nexis Uni
(provided by LexisNexis)** search exports. Nexis is a restricted source: the search
**results** (case/news records) are excluded from the public package. This document
makes the **extraction explicit** (JPE Policy 2.1) — for a search-based source the
"extraction program" is the **search query**, and here **each export file's name is
the literal Nexis search string** it was produced from.

## How the data was obtained
1. In Nexis Uni, run each search listed below.
2. Export the **"Results list"** (the case/document hit list). Nexis names the export
   `Results list for [your search].(xlsx|zip)` — so the **filename is the query**.
   In the filenames, underscores stand in for the Nexis search syntax: `_phrase_`
   = a quoted phrase, `AND`/`NOT` = Boolean operators, `date _YYYY` / `date _ YYYY`
   = the from/to date filter.
3. The exported Results lists are stored in `data/raw/Liability/` (and
   `data/raw/Liability/medtech/` for bankruptcy). **Excluded from the public package**
   (restricted); available to the Data Editor via the Nexis route.

## The searches (filename = query)
**Medical-device tort, by period:** `medical device tort` for 1985–1995, 1996–2000,
2001–2004, 2005–2007.

**Medical-device tort *preemption*:** `medical device tort preempt` overall; by class
(`_Class II_`, `_Class III_`); 2006–2007; and `NOT pharma`.

**Medical-device tort by class / device:** `_medical device_ tort _Class II_`;
`_medical device_ _Class II_ tort preempt`; `medical device tort _hospital bed_ powered`.

**Pharmaceutical tort preemption (separated from devices):** `pharmaceutical tort
preempt` for 1985–1998, 1999–2004, 2005–2007; and `NOT device` variants
(1985–2001, 2002–2007, and an `85-01` zip).

**Medical-device bankruptcy (`medtech/`, 14 files):** `_medical device_ AND
_Chapter 11_ AND bankruptcy` with rolling overlapping date windows
(`date _YYYY AND date _ YYYY+2`) spanning ~1989–2007.

## Search environment & export settings (for an exact rerun)
- **Content type:** Nexis Uni **Cases** (legal case law). Each export is the
  **Results list** view, not full documents. Export schema (columns the code relies
  on): `CASE NAME, CITE, SUMMARY, JURISDICTION, COURT, DATE DECIDED, YEAR`
  (`11c_liability.py` groups on `YEAR` and counts `CITE`).
- **Jurisdiction:** all U.S. federal and state courts (no jurisdiction restriction);
  the `date _YYYY` tokens in the filenames are the **Decision-date** range filter.
- **Access/export vintage (multi-vintage archived exports).** The Results lists were
  not pulled in a single session. The **internal workbook (`.xlsx` ZIP-member)
  timestamps, used as export-vintage evidence** (not an independently certified Nexis
  export date), span 2023–2024:
  - **Tort/preemption** (17 files): **2023-07-25/26** for 14 files (the bulk of the
    tort and preemption searches); **2023-08-22** for `_medical device_ _Class II_ tort
    preempt` and **2023-08-23** for `_medical device_ tort _Class II_`; **2023-11-06**
    for `medical device tort _hospital bed_ powered`.
  - **Bankruptcy** (`medtech/`, 14 files): all **2024-08-27**.

  Because the exports are this spread out — and because Nexis revises its corpus
  retroactively — hit counts from a later rerun can differ; this is the central reason
  the **raw archived exports are the primary verification route** (see the caveat
  below), not a contemporary re-search.
- **File format / case:** export to **`.xlsx`** with a **lowercase** extension. The
  code reads lowercase `.xlsx` (`11c_liability.py:141`); uppercase `.XLSX` exports work
  on case-insensitive macOS but **fail on Linux**. The package's bankruptcy files have
  been normalized to lowercase `.xlsx`, and any new export must match.
- **Sort/dedup:** Nexis default relevance sort; no manual de-duplication (the code
  counts rows as returned).
- **Non-proprietary mirror (JPE Policy 1.4):** because `.xlsx` is a proprietary
  format, each of the 31 Results-list workbooks has a UTF-8 **CSV mirror** alongside it,
  generated by `code/00_generate_data/convert_nexis_to_csv.py`.
  `data/raw/Liability/NEXIS_FORMAT_MIRROR_HASHES.csv` records the SHA-256 and row count
  of both the `.xlsx` and its `.csv`. The mirrors are restricted (excluded from the
  public package) and travel with the raw exports in the Nexis route; `11c_liability.py`
  reads the `.xlsx`, and the CSV is the format-open companion.

## From exports to analysis
- `code/11c_liability.py` reads the **raw Results-list exports directly** — e.g.
  `pd.read_excel("Results list for_medical device tort preempt.xlsx")` (tort/
  preemption, lines ~67) and the `medtech/…Chapter 11…bankruptcy…` exports (lines
  ~141) — concatenates them, and counts cases by year and type to build **Appendix
  Figure D.9**. It does **not** read any GPT-coded file for this exhibit.
- `FDB Device export_07-05-2023 *.xlsx` is an FDA device cross-reference that is
  **not read by any analysis code** (unused); it is therefore not CSV-mirrored.
- The `Liability_Encodings_*_gpt4.csv` files are a separate GPT-4 case-coding and are
  **not** read by `11c_liability.py` for Figure D.9 (do not rely on them to reproduce it).

## Reproducing the extraction (Nexis route) — TWO options
Because `11c_liability.py` consumes the **raw** Nexis Results-list exports, the
exhibit cannot be reproduced from derived coding alone.

**(a) Confidential raw exports — primary route.** The author provides the raw
Results-list `.xlsx` exports (tort/preemption under `data/raw/Liability/`, bankruptcy
under `data/raw/Liability/medtech/`) to the Data Editor under confidentiality; run
`code/11c_liability.py`. This is the **recommended** route: it reproduces Figure D.9
exactly because it uses the **original archived result sets** (tort/preemption pulled
2023-07 through 2023-11; bankruptcy 2024-08). A contemporary rerun (option b) may not
match, because Nexis revises case coverage over time.

**(b) Search-and-export protocol — best-effort.** In Nexis Uni (content type
**Cases**), run each search listed above (the filenames are the exact queries),
**export each Results list to `.xlsx` with a lowercase extension, using the same
filename**, place the tort/preemption files in `data/raw/Liability/` and the
bankruptcy files in `data/raw/Liability/medtech/`, then run `code/11c_liability.py`.
The script reads files by their **exact** names (and lowercase `.xlsx`), so names and
extension case must match. Confirm the rerun against the **expected hit counts** table
above; small deviations are expected from Nexis corpus updates and do not change the
qualitative trends, but a large miss means a search/filter was set differently (check
content type = Cases, jurisdiction = all, and the decision-date window).

No Nexis records are publicly redistributed; only the queries and this protocol are
documented here.
